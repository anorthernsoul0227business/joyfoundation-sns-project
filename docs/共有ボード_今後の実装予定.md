# 共有ボード：今後の実装予定

2026-09-02、康二郎さんから依頼。優先度は「後回しでよい」とのことなので、
まずは記事レビューの運用を安定させたうえで、上から順に着手する。

## 1. 画像の直接アップロード

**要望**: iPhone / PC からドラッグ＆ドロップのように直接アップロードしたい。
Google Drive に一度上げる形ではなく、記事欄に直接上げて、自動で DB に保存されるのが理想。

**現状**: 画像は Drive に置き、`DriveImagePicker`（653行の Python 側処理）で選ぶ。
週次ループが `=IMAGE(...)` の数式でシートに貼っている。

**方針案**:
- 記事詳細に drop zone を置き、`<input type="file">` + drag/drop の両対応（iPhone は
  「写真を選ぶ」ボタンとして機能する）
- ブラウザ側で長辺 1600px 程度にリサイズしてから送る（回線とストレージの節約）
- 保存先は Cloudflare R2（投稿ジョブが既に R2 の公開URLを読んでいるため）。
  Next.js の Route Handler で署名付きURLを発行し、ブラウザから直接 PUT する
- アップロード完了後に `attachments` へ INSERT（`owner_type='article'`）
- Drive 経由の既存経路は当面残す（過去記事の画像が Drive にあるため）

## 2. 投稿済みカレンダーと再投稿

**要望**: 投稿した過去の記事をカレンダーで見やすく、検索もできるように。
X / Instagram は似た記事やイベントを編集して再投稿しやすくしたい。

**方針案**:
- 既存の `/calendar` 画面（86kB、実装済み）を `articles` テーブルに繋ぎ直す
- `status='published'` + `published_at` で月表示。媒体ごとに色分け
- 全文検索は Postgres の `to_tsvector`（日本語は分かち書きが要るので、
  まずは `ILIKE` の部分一致で始めて様子を見る）
- 「これをもとに新しく作る」ボタン → 本文をコピーした新規記事を `ai_draft` で作成。
  `source_card_ids` と画像も引き継ぐ

## 3. 思いつきメモに LLM / チャットボット

**要望**: つぶやくコーナーで直接会話できるようにしたい。

**最終形（2026-09-02 康二郎さん）**:
**康二郎さんを通さず、圭一郎さんと AI だけで完結する**状態に持っていく。
AI が迷うことが出てきたら、康二郎さんと圭一郎さんで話し合い、その結果を開発に反映する
（＝迷いは「その場で人に聞く」のではなく「設計に戻して次から迷わなくする」）。

**方針案**:
- `ideas` に紐づくスレッド（`idea_messages`）を足し、圭一郎さんの発言に AI が応答
- 週次ループの知識層（`knowledge/evidence/` の承認済みカード）を参照させ、
  既存カードと矛盾しない範囲で話す
- 思いつき → 記事の種 → 下書き まで、この会話の中で進められるようにする
- AI が答えを持たない／判断がぶれる話題は、答えを作らずに
  **「保留」として記録**し、康二郎さんの手元に一覧で溜まるようにする。
  康二郎さんと圭一郎さんで話した結果をルール化して AI に反映する

**段階**:
1. 会話ができる（記録だけ。記事化は康二郎さんが手動）
2. 会話から下書きを作れる（承認は従来どおり）
3. 圭一郎さんの承認だけで投稿まで進む（下記の但し書きを解いてから）

**設計上の注意（実装前に決めたいこと）**:
- このコーナーは圭一郎さんが気軽に書く場所。AI が毎回返事をすると
  「返さなければ」という負担になるので、応答の頻度と長さは控えめにする
- **分級 C（新規の数値・ニュース・医療的表現）の扱いが最大の論点**。
  現在の安全設計は「康二郎さんが目を通すこと」に依存しており、
  そこを外すと健康・研究の話題で誤りが出たときに止める人がいなくなる。
  段階3に進む前に、たとえば次のどれかを用意しておきたい:
  - AI は承認済みカードの範囲でしか書かない（新規の数値・出典を持ち出さない）
  - 分級 C に該当したら自動で保留にし、圭一郎さんにも「これは出せません」と伝える
  - 投稿後でも取り消せる導線を圭一郎さんの画面に置く
