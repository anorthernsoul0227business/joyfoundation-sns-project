## 1. 提案の骨子

**「実証実験はスマホ＋車載Bluetoothスピーカーで最小構成、量産フェーズで専用機器／OEM組込みへ移行」の2段構え（ハイブリッド案）を推奨する。**

理由:
- 短期の実証実験は「どんな音・どんな方式が良いか」の検証が目的であり、初期投資を抑えて素早く始められる構成が適する
- 打ち合わせでもスマホは「一番フレキシブルでどんな状態でも対応できる」と有力視されている
- 数百台規模・トヨタ等との連携という長期像は、実証データを持ってから専用設計に進む方が説得力がある

## 2. 方式比較

| 観点 | A案: スマホアプリ | B案: 専用再生機器 | C案: ハイブリッド（推奨） |

| 初期費用/台 | 低（既存スマホ流用なら実質スピーカー代のみ） | 中〜高（機器設計・製造） | 段階に応じ最適化 |

## 3. 実証実験フェーズの推奨構成（C案・第1段階）

### 3.1 再生デバイス: スマホ（会社支給を推奨）

- **専用アプリ**（iOS/Android）を限定配布（TestFlight / 限定APK / MDM配布）
  - 起動 → 大きな再生ボタン1つだけの画面（走行中操作なしの思想をUIで担保）
  - 端末の時計で朝・昼・夜を判定し自動選曲（F2）。ドライバーに選択させない
  - **音源は端末内蔵（オフライン再生）**: 全国走行で通信が不安定なエリアがあるため。配信更新はWi-Fi接続時のみ
- 私物スマホは避け、**会社支給端末**を推奨（要件書の要確認事項#3）
  - 理由: 音量・通知・他アプリの干渉を統制できない私物では実験条件が揃わない
- 固定はカップホルダー型 or エアコン吹き出し口マウント（打ち合わせで言及のあった案）

### 3.2 スピーカー: 車載Bluetoothスピーカー（サンバイザー/ヘッドレスト周辺）

- トラック純正オーディオは車両により仕様がバラつくため、実証では**後付けスピーカーで条件を統一**
- 「音のシャワーのように顔や体に降り注ぐ」(F4)を満たす設置位置を実車で検証
  - 候補: サンバイザー裏 / ヘッドレスト両脇 / ダッシュボード上
- **体感音響の選択肢**: ジョイファウンデーションの小型体感音響機器（Harmonic Massage）を座席に組み合わせる拡張実験も提案可能。「乗れば健康になる」の差別化要素として有力
- Bluetooth接続はエンジンON→自動再接続を事前検証（接続切れは実験の信頼性を損なう）

### 3.3 音源管理

- 朝・昼・夜 × 複数バリエーション（森・海・高原）をプレイリスト化
- 音源選定・差し替えはジョイ側の管理画面（簡易でよい: 実証中は手動更新で十分）
- 著作権・複製管理: 限定配布＋端末内暗号化格納で流出リスクを抑制

### 3.4 実証実験の設計案（先方への逆提案）

| 項目 | 案 |
|---|---|
| 規模 | 5〜10台・10〜20名（都市部/地方の両方を含める） |
| 期間 | 4〜8週間（前半2週は音なしのベースライン計測を推奨） |
| 評価指標 | 主観疲労度アンケート（乗務前後）／睡眠の質／ヒヤリハット件数／可能ならウェアラブルで心拍変動 |
| 比較設計 | 音あり期間 vs 音なし期間の同一ドライバー内比較 |

※ エビデンス提示が本件のきっかけであるため、実証実験も測定設計をきちんと組むことが先方の期待に合致する

## 4. 量産フェーズの構成（C案・第2段階）

- 実証結果を基に専用再生機器（物理スイッチ＋内蔵ストレージ＋専用アンプ）を設計
- スピーカー設置位置は実証で得た最適位置を「指定位置」としてトヨタ・いすゞへの要請に使う
- 将来の車両標準搭載時は、機器仕様をOEM側に提供する形へ移行
- 夜間睡眠環境・工場向けは同じ音源資産＋別ハード（据置スピーカー）で横展開

## 5. 概算イメージ（実証フェーズ・1台あたり）

| 項目 | 概算 |
|---|---|
| スマホ（支給する場合） | 3〜5万円（中古/廉価Android可） |
| Bluetoothスピーカー＋マウント | 0.5〜1.5万円 |
| アプリ開発（初期・全体で） | 規模により要見積（最小: 再生＋時間帯切替のみ） |
| 音源制作・編集 | ジョイ側既存資産の再編集が中心 |

## 6. リスク・検討事項

1. **道路交通法・安全面**: 走行中に操作させないUI設計は法令面でも必須。音量上限の設計（警音・緊急車両サイレンをマスキングしない）
2. **Bluetooth自動再接続の信頼性**: 機種依存が大きい。実証前に候補機器で検証
3. **夏場の車内高温**: スマホ・スピーカーの耐熱（ダッシュボード上は特に）
4. **ドライバー受容性**: 「監視されている」と感じさせない説明・同意設計
5. **効果表現**: 「効果があります」等の断言はNG（既存SNSルールと同様、エビデンスは「〜が報告されています」トーンで）
